# QA Checklist

## Shell and support pages
- [ ] Version pill is visible.
- [ ] Environment pill is visible and meaningful.
- [ ] Theme toggle switches light/dark mode.
- [ ] Theme persists after refresh/reopen.
- [ ] Help page opens.
- [ ] Feedback page opens.
- [ ] Return navigation works from Help and Feedback.

## Launcher
- [ ] Launcher shows all scenario families.
- [ ] Scenario cards display concept tags and difficulty labels.
- [ ] Resume state appears when a saved mission exists.
- [ ] Starting a scenario opens the mission workspace.

## Mission workflow
- [ ] Mission brief displays learning objective and “Why this matters.”
- [ ] Prediction step allows a clear weak-state forecast.
- [ ] Guided repair buttons modify the package.
- [ ] Direct component include/exclude controls work.
- [ ] Compare view updates after meaningful changes.
- [ ] Metrics update after meaningful changes.
- [ ] Maturity state updates logically.
- [ ] Debrief area accepts a response.
- [ ] Reset mission works.
- [ ] Harder replay works.

## Manual-run support
- [ ] Copy-ready package block is visible.
- [ ] Observation checklist is visible.
- [ ] Paste-back area accepts text.
- [ ] Prepared fallback output changes with stronger/weaker readiness.

## Chapter fidelity and learning quality
- [ ] Terminology aligns to Chapter 1, not Chapter 2 lifecycle language.
- [ ] The app remains learner-first and not builder-first.
- [ ] Weak and stronger package states create understandable contrasts.
- [ ] Coaching explains cause-and-effect in plain language.
- [ ] Optional Explore More feels additive, not required for completion.

## Responsiveness and accessibility
- [ ] Primary workflow remains usable on narrow screens.
- [ ] Focus styling is visible.
- [ ] Color is not the only signal for warnings or progress.
- [ ] Reduced-motion users are respected through CSS.
