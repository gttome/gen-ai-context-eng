Reliability Triage Console

How It Works

Use this console to practice Chapter 4 reliability triage: diagnose the visible symptom, anchor to the source of truth, choose the smallest credible mitigation, and preserve the lesson with a regression check.

Core flow

  1. Review the mission brief and the broken output.
  2. Inspect the governing source-of-truth materials and nearby clues.
  3. Work through the first five checks.
  4. Select the primary failure mode and likely root cause.
  5. Choose the smallest credible mitigation.
  6. Add a concrete regression check.
  7. Review, compare, and export the triage record.

Scenario pack

  • Missing grounding — policy answer sounds confident but is not anchored to the governing source.
  • Format drift — content may be plausible, but the answer violates the required operational schema.
  • Stale context — the answer follows an outdated snippet instead of the current authoritative source.
  • Trust-boundary hard mode — quoted override text tries to outrank the actual governing policy.
  • Mixed signals hard mode — a polished answer contains both a secondary format miss and a more serious unsupported claim.

Replay analytics

Summary now includes replay analytics so the learner can see recent trend, best score, and average score for the current scenario. This is meant to make improvement visible across repeated Chapter 4 triage runs, not to gamify the app with noisy dashboards.

Manual external-LLM loop

The console stays static by design. When a case calls for validation, copy the prepared packet, run it in an external LLM, paste the answer back into the review frame, and inspect whether the new answer shows stronger control signals.

What good performance looks like

  • Evidence Discipline: you inspected the source that should have governed the answer.
  • Failure-Mode Fit: your diagnosis matches the visible evidence better than nearby alternatives.
  • Mitigation Restraint: you selected a focused, testable change instead of a broad rewrite.
  • Regression Thinking: you preserved the lesson with a future check.

Worked sample triage record

Scenario: Policy Answer with Missing Grounding

Source of truth: Current travel policy excerpt

Primary failure mode: Hallucination / missing evidence

Likely root cause: The system answered decisively without grounding to the policy or using the uncertainty fallback.

Smallest credible mitigation: Require section citation or explicit uncertainty before yes/no policy answers.

Regression check: Spouse-airfare reimbursement answers must cite Section 4.2 or escalate under Section 4.3.

Navigation support

The mission now uses a simpler main layout and a fixed bottom mission coach dock. Live score, delta, risk, replay trend, and next-step coaching stay visible there while deeper guidance opens in small popup panels only when needed.

Need to restart? Use Replay mission after summary or Reset this step inside the current diagnostic phase. Open the Coach, Impact, or Playbook popups from the bottom dock whenever you want more guidance without losing your place. On harder scenarios, use replay analytics after summary to see whether your latest mitigation discipline actually improved.
