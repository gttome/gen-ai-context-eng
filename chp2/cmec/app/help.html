How the core mission works

  1. Choose a scenario family on the launcher.
  2. Read the mission brief, concept focus, and “Why this matters” note.
  3. Inspect the visible weak package first so you can see what the model actually gets and what is missing.
  4. Use the coaching hints to predict the most likely failure mode.
  5. Apply one or more guided repairs or toggle package components directly.
  6. Watch the live metrics, compare view, and coaching update.
  7. Optionally copy the current package into an external LLM and paste the result back.
  8. Finish the debrief, then replay or open Explore More.

What each metric means

  • Signal Quality: Are the included components specific and relevant?
  • Grounding: Did you give the model approved facts instead of forcing it to guess?
  • Structure: Will the model return a reusable answer shape?
  • Continuity: Did you carry forward the right prior-turn context?
  • Overload Risk: Is the context package too noisy or too large for the mission budget?
  • Mission Readiness: Is the package reliable enough for a stronger run?

Mission design intent

This app is deliberately learner-first. You are not building documents from scratch. You are repairing prepared weak packages so you can see cause-and-effect quickly.

That means the weak package should be visible before prediction, and small changes should create visible changes in metrics, coaching, and compare surfaces. If you are not seeing movement, make sure at least one meaningful repair was applied.

Troubleshooting

  • If the app looks blank, run start-server.bat and open the local URL instead of double-clicking index.html.
  • If progress seems stale, use the mission reset control on the launcher.
  • If theme does not persist, confirm browser storage is enabled.
  • If you want to continue in a new chat, upload the app ZIP and start with project-documents/handoff-startup-prompt.md.
